# City2City Route Scoring Pipeline — Project Overview

> **Проект:** Автоматизированный скоринг и сегментация маршрутов межгородского такси
> **Сайт:** city2city.ru
> **Дата создания:** 22–24 февраля 2026
> **Статус:** Основной пайплайн завершён ✅ | Сбор 109K новых маршрутов в процессе ⏳

---

## 1. БИЗНЕС-КОНТЕКСТ

**city2city.ru** — агрегатор межгородского такси. На сайте ~4 200 маршрутных страниц (формат `/moskva-kazan`, `/rostov-ufa`). Каждая страница — отдельная SEO-единица.

**Задача проекта:** Определить для каждого маршрута оптимальный канал привлечения трафика:
- **SEO** (органическая выдача Яндекса) — для маршрутов со слабой конкуренцией
- **Яндекс.Директ** (платная реклама) — для маршрутов с высоким чеком
- **Автопилот** — маршруты, которые уже ранжируются без усилий
- **Игнорировать** — маршруты без поискового спроса

В базе данных сайта ~114 000 маршрутов, из которых 4 204 были выгружены для приоритетного анализа.

## 3. СИСТЕМА СКОРИНГА

### 3.1 Четыре оси оценки

| Метрика | Формула | Диапазон | Описание |
|---|---|---|---|
| **demand_score** | log-нормализация total_freq | 0–1 | Поисковый спрос (частотность «такси X Y») |
| **competition_score** | 0.5×federal + 0.3×(1−local) + 0.2×total_norm | 0–1 | Сила конкурентов в выдаче Яндекса |
| **position_score** | TOP-3→1.0, TOP-10→0.7, TOP-20→0.4, TOP-30→0.2 | 0–1 | Текущая позиция city2city.ru |
| **weakness_score** | 1 − competition_score | 0–1 | Слабость конкурентов (инверсия) |

### 3.2 Пороги классификации

| Порог | Значение | Назначение |
|---|---|---|
| HIGH_DEMAND | ≥ 0.5 | Высокий спрос |
| MEDIUM_DEMAND | ≥ 0.2 | Умеренный спрос |
| WEAK_COMPETITION | ≥ 0.5 | Слабая конкуренция |
| CLOSE_POSITION | ≥ 0.4 | City2city близко к ТОП-10 |
| DIRECT_PRICE | ≥ 10 000₽ | Порог для Яндекс.Директ |

### 3.3 Логика классификации

```
if demand == 0 → IGNORE

if price ≥ 10K:
  if demand HIGH:
    if weakness HIGH:
      if position CLOSE → SEO_GOLD_DIRECT
      else             → SEO_INVEST_DIRECT
    else:
      → DIRECT_ONLY
  elif demand MEDIUM → DIRECT_TEST
  else               → DIRECT_LOW

if price < 10K:
  if demand HIGH:
    if weakness HIGH:
      if position CLOSE → SEO_GOLD
      else             → SEO_INVEST
    else:
      if position CLOSE → SEO_DEFEND
      else             → SEO_HARD
  elif demand MEDIUM:
    if weakness HIGH   → SEO_AUTOPILOT
    else               → SEO_MONITOR
  else → IGNORE
```

## 10. ИСПРАВЛЕННЫЕ ПРОБЛЕМЫ

### 10.1 Пустой city_to (208 маршрутов)
**Проблема:** 208 из 4204 маршрутов имели пустое поле city_to. Wordstat запросы формировались как «такси Москва» вместо «такси Москва Тула» → нулевая или нерелевантная частотность.

**Причина:** Slug-парсер не обрабатывал сложные URL: `svo-taxi-donetsk-lugansk`, `ekaterinburg-sibaj`, составные города (`Ростов-на-Дону`), префиксы (`село`, `рабочий посёлок`).

**Решение:** `fix_city_to_v2.py` — трёхуровневый маппинг:
1. Полная карта slug→город из `all_routes_db.tsv` (~4000 записей)
2. Ручной словарь для SVO-такси и сложных маршрутов (~100 записей)
3. Prefix matching по городам-отправления

**Результат:** 205 из 208 починено автоматически, 3 не найдены (ошибки в API).

### 10.2 BOM-кодировка
**Проблема:** `routes_city2city_fixed2.csv` содержит BOM (Byte Order Mark). `final_scoring.py` читал с `encoding="utf-8"` → KeyError на первом поле.

**Решение:** Заменено на `encoding="utf-8-sig"` в `load_routes()`.

### 10.3 Потеря 950 маршрутов при join
**Проблема:** При первом запуске `final_scoring.py` использовалась неполная `ws_cloud_results.csv` → 950 маршрутов показывали freq=0.

**Решение:** Перезапуск с полными данными (ws_cloud_results_v2.csv).

### 10.4 Type error в recollect_208.py
**Проблема:** Yandex API возвращает `totalCount` как строку. Сравнение `r['total_count'] > 0` давало TypeError.

**Решение:** Обёртка `int()` для всех числовых полей из API.
