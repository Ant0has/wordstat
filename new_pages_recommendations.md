## ОБЗОР СИТУАЦИИ

### Что было сделано
Из ~109K маршрутов в базе данных city2city.ru были собраны данные Wordstat и SERP для 7,501 маршрута с ненулевой частотностью. После фильтрации шума (SVO-такси, межгород-агрегаторы, одногородские маршруты) получено **6,601 реальный межгородский маршрут**.

### Текущее состояние сайта
- **is_indexable=1** в MySQL: 1,748 маршрутов → теперь **4,913** (+3,165)
- **Sitemap**: 4,272 URL → **7,437** (+3,165)
- **Whitelist**: 4,265 → **8,150** (+3,885)
- Маршруты в БД: ~114,000 (все доступны, 404 только если нет в БД)

### Архитектура блокировки
| Механизм | Статус | Что делает |
|---|---|---|
| middleware.ts (root) | **Активен** | Только добавляет .html суффикс (301 редирект) — НЕ блокирует |
| app/middleware.ts | **Мёртвый код** | Whitelist-проверка НЕ работает (неверное расположение для Next.js 13+) |
| API (routes.service) | **Активен** | Отдаёт маршрут если есть в БД, иначе 404 |
| is_indexable | **Активен** | Контролирует noindex meta-тег (0 = noindex, 1 = index) |
| excludesPages | **Активен** | ~30 брянских маршрутов принудительно noindex |

**Вывод:** 301 редирект на .html — штатное поведение для ВСЕХ страниц, не является блокировкой. Маршруты из 109K уже были доступны (они есть в БД), но имели `is_indexable=0` (noindex).

## КОМПРОМИССНОЕ РЕШЕНИЕ

### Принятая логика

| Категория | Критерий | Действие | Кол-во |
|---|---|---|---|
| **RETURN_FULL** | freq > 10 ИЛИ city2city в ТОП-10 ИЛИ сегмент не LOW_PRIORITY | whitelist + sitemap + is_indexable=1 | **3,165** |
| **RETURN_NOINDEX** | freq 1-10 И city2city в ТОП-30 (позиции 11-30) | whitelist (is_indexable=0, noindex) | **721** |
| **SKIP** | freq 1-10 И нет в ТОП-30 | Оставить как есть | **2,715** |

**Итого возвращено: 3,886** маршрутов (3,165 полностью + 721 в режиме noindex)

### Почему этот подход оптимален
1. **3,165 маршрутов для индексации** — имеют подтверждённый спрос или уже ранжируются
2. **721 маршрут noindex** — страницы доступны для пользователей (переход по ссылкам), но не индексируются. Можно перевести в index после улучшения контента
3. **2,715 пропущено** — нет спроса (freq 0-10) и нет позиций. Нет смысла индексировать шаблонные страницы

## ПРОБЛЕМА ТОНКОГО КОНТЕНТА И ШАБЛОННОСТИ

### Текущее состояние страниц
Новые 3,886 страниц, скорее всего, имеют шаблонный контент:
- Одинаковый текст с подстановкой городов
- Минимум уникальной информации
- Нет отзывов, FAQ, описания маршрута
- Возможно отсутствует цена (поле `price` = NULL в БД)

### Риски шаблонного контента
1. **Фильтр тонкого контента Яндекса** — может применить пессимизацию ко всему сайту
2. **Каннибализация** — шаблонные страницы могут вытеснять качественные из выдачи
3. **Рост показателя отказов** — пользователь не находит полезной информации

### Стратегия борьбы с шаблонностью

#### Приоритет 1: Уникализация 254 маршрутов (не LOW_PRIORITY)

Для каждой страницы обеспечить:

**Обязательный минимум:**
- Уникальный Title: "Такси [Город1] — [Город2] от [цена]₽ | Заказать онлайн"
- Уникальный H1: "Заказать такси [Город1] — [Город2]"
- Meta description с ценой, расстоянием, временем в пути
- Блок с ценой (если price != NULL в БД)
- Расстояние между городами (можно сгенерировать)
- Время в пути (можно рассчитать из расстояния)

**Желательно:**
- 3-5 FAQ (как заказать, что включено, время подачи, багаж, детское кресло)
- Блок "Похожие маршруты" (перелинковка с соседними городами)
- Отзывы (минимум 3 на страницу)
- Описание маршрута (2-3 предложения о дороге, достопримечательностях)
- Schema.org разметка TaxiService

#### Приоритет 2: Массовая оптимизация 2,911 LOW_PRIORITY FULL

Так как это 2,911 страниц, ручная работа невозможна. Стратегия:

1. **Шаблонный генератор контента:**
   - Автоматическое создание текста с уникальными данными для каждого маршрута
   - Источники уникальности: расстояние, время пути, цена, регион, промежуточные города
   - 5-7 вариантов шаблона, чтобы не было 100% одинаковых текстов

2. **Микроразметка (Schema.org):**
   ```json
   {
     "@type": "TaxiService",
     "areaServed": {"@type": "City", "name": "Город1"},
     "serviceArea": {"@type": "City", "name": "Город2"},
     "offers": {"@type": "Offer", "price": "ЦЕНА", "priceCurrency": "RUB"}
   }
   ```

3. **Автоматические FAQ:**
   - "Сколько стоит такси [Город1] — [Город2]?" → ответ с ценой
   - "Сколько ехать от [Город1] до [Город2]?" → ответ с временем
   - "Как заказать такси?" → стандартный ответ
   - "Можно ли с детским креслом?" → стандартный ответ

4. **Перелинковка:**
   - Каждая страница маршрута ссылается на обратный маршрут
   - Блок "Другие маршруты из [Город1]" (3-5 ссылок)
   - Блок "Популярные маршруты в [Город2]" (3-5 ссылок)

#### Приоритет 3: 721 NOINDEX маршрутов

Эти страницы уже noindex. Стратегия:
1. Улучшить контент массовым шаблоном (как для LOW_PRIORITY FULL)
2. Через 1-2 месяца проверить позиции
3. Если появились позиции → перевести в is_indexable=1 и добавить в sitemap
4. Если нет позиций → оставить noindex или удалить

## КОНКУРЕНТНЫЙ ПРОФИЛЬ НОВЫХ МАРШРУТОВ

### Средние показатели для RETURN_FULL (3,165 маршрутов)

| Тип конкурента | Среднее кол-во в ТОП-10 | Описание |
|---|---|---|
| Федеральные агрегаторы | 16.1 | taksisvo.ru, deshevotaxi.ru, mejgorodtaxi.ru, kiwitaxi.ru и др. |
| Региональное такси | 9.2 | Местные таксомоторные компании |
| Яндекс-сервисы | 2.3 | taxi.yandex.ru, yandex.ru, go.yandex |

### Выводы по конкуренции
- **Федеральные агрегаторы** — основные конкуренты. Их страницы часто шаблонные → city2city может обойти за счёт уникального контента
- **Региональное такси** — точечная конкуренция, не во всех регионах
- **Яндекс** — присутствует, но не доминирует. На 2.3 позиции из 10 в среднем

### Стратегия vs конкурентов
1. **Цена на странице** — главное преимущество. Многие агрегаторы не показывают цену
2. **Форма заказа** — возможность заказать прямо на странице
3. **Отзывы** — социальное доказательство
4. **Скорость загрузки** — Next.js даёт преимущество над PHP-сайтами конкурентов
