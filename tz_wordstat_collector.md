# ТЗ: Скрипт массового сбора частотности из Яндекс Вордстат

## Цель

Автоматизированный сбор данных о частотности поисковых запросов по маршрутам city2city.ru через новый API Яндекс Вордстат (api.wordstat.yandex.net). Результат — база частотностей для приоритизации SEO-страниц и оценки спроса по маршрутам.

---

## API: Новый Яндекс Вордстат (НЕ через Директ)

### Базовая информация

| Параметр | Значение |
|---|---|
| Эндпоинт | `https://api.wordstat.yandex.net` |
| Протокол | HTTPS, метод POST |
| Формат | JSON |
| Авторизация | `Authorization: Bearer <OAuth-токен>` |

### Ключевое отличие от старого API (через Директ)

Старый API (Директ) требовал создавать отчёты, ждать генерации, забирать результат. Новый API — **синхронный**: отправил запрос → мгновенно получил ответ. Никаких отчётов, очередей, ожидания. Один запрос = одна фраза = один ответ.

### Доступные методы

| Метод | Описание | Расход квоты |
|---|---|---|
| `/v1/topRequests` | Топ запросов по фразе + похожие запросы (за 30 дней) | 1 единица |
| `/v1/dynamics` | Динамика числа запросов по фразе во времени | 1 единица |
| `/v1/regions` | Распределение запросов по регионам | 1 единица |
| `/v1/getRegionsTree` | Дерево всех регионов Вордстат (справочник) | бесплатно |
| `/v1/userInfo` | Информация о квоте пользователя | бесплатно |

### Основной метод: `/v1/topRequests`

**Запрос:**
```json
POST https://api.wordstat.yandex.net/v1/topRequests
Authorization: Bearer <token>
Content-Type: application/json

{
  "phrase": "такси Москва Санкт-Петербург",
  "regions": [213, 2],
  "devices": ["desktop", "phone", "tablet"],
  "numPhrases": 50
}
```

**Параметры запроса:**

| Параметр | Обязательный | Описание |
|---|---|---|
| `phrase` | Да | Поисковая фраза |
| `regions` | Нет | Список ID регионов (по умолчанию — вся Россия) |
| `devices` | Нет | Типы устройств: `desktop`, `phone`, `tablet` |
| `numPhrases` | Нет | Количество фраз в ответе (по умолч. 50, макс. 2000) |

**Ответ:**
```json
{
  "requestPhrase": "такси москва санкт-петербург",
  "totalCount": 12500,
  "topRequests": [
    {"phrase": "такси москва санкт-петербург цена", "count": 3200},
    {"phrase": "такси москва питер", "count": 2800},
    ...
  ],
  "associations": [
    {"phrase": "трансфер москва петербург", "count": 1500},
    ...
  ]
}
```

**Ключевые поля ответа:**

| Поле | Описание |
|---|---|
| `requestPhrase` | Заданная фраза |
| `totalCount` | Общее число запросов, содержащих все слова фразы |
| `topRequests[]` | Популярные запросы, содержащие слова фразы (phrase + count) |
| `associations[]` | Похожие запросы (аналог правой колонки Вордстат) |

### Лимиты API

| Параметр | Значение |
|---|---|
| Квота по умолчанию | 1 000 запросов/сутки |
| Запрошенная квота | 5 000 запросов/сутки |
| Rate limit | 10 запросов/секунду |
| Стоимость 1 запроса | 1 единица квоты |
| Ошибка превышения квоты | HTTP 429 |
| Ошибка перегрузки API | HTTP 503 |

## Масштаб задачи

- ~4 093 маршрута в базе city2city
- На каждый маршрут — 5 шаблонов фраз → ~20 000 фраз
- 1 фраза = 1 запрос к API
- При квоте 5 000/сутки → **полный сбор за 4 дня**
- При квоте 1 000/сутки → полный сбор за 20 дней
- При 10 запросов/сек → одна суточная квота выбирается за ~8 минут

## Функциональные требования

### 1. Генерация фраз по шаблонам

На вход — CSV со списком маршрутов:

```
город_откуда;город_куда
Москва;Санкт-Петербург
Москва;Тула
...
```

Шаблоны фраз (настраиваемые через конфиг):

| Шаблон | Пример |
|---|---|
| `такси {откуда} {куда}` | такси Москва Санкт-Петербург |
| `трансфер {откуда} {куда}` | трансфер Москва Санкт-Петербург |
| `межгород {откуда} {куда}` | межгород Москва Санкт-Петербург |
| `такси {откуда} {куда} цена` | такси Москва Санкт-Петербург цена |
| `{откуда} {куда} на машине` | Москва Санкт-Петербург на машине |

Шаблоны хранятся в конфиге, легко добавляются/удаляются.

### 2. Сбор данных через `/v1/topRequests`

Для каждой сгенерированной фразы:

- Отправить POST-запрос к `/v1/topRequests`
- Получить `totalCount` (основная частотность)
- Получить `topRequests[]` (вложенные запросы)
- Получить `associations[]` (похожие запросы)
- Параметр `numPhrases` = 50 (достаточно для анализа)

Управление скоростью:

- Не более 10 запросов/секунду (лимит API)
- Настраиваемая пауза между запросами (по умолч. 0.15 сек = ~7 rps)
- Перед стартом — вызов `/v1/userInfo` для проверки оставшейся квоты
- При HTTP 429 — остановка до следующих суток или до refill

### 3. Возобновляемость (resume)

Критически важно — сбор может занять несколько дней:

- Сохранение прогресса после каждого запроса в `progress.json`
- При повторном запуске — пропуск уже собранных фраз
- Файл состояния хранит: какие фразы обработаны, текущую позицию, дату
- Корректное завершение по Ctrl+C с сохранением

### 4. Дополнительный сбор: `/v1/regions` (опционально)

Для топ-маршрутов (по totalCount) — региональный разрез:

- Вызвать `/v1/regions` для топ-200 маршрутов
- Получить распределение спроса по регионам
- Поля: `regionId`, `count`, `share`, `affinityIndex`
- Это поможет понять, откуда идёт спрос

### 5. Дополнительный сбор: `/v1/dynamics` (опционально)

Для топ-маршрутов — сезонность:

- Вызвать `/v1/dynamics` для топ-100 маршрутов
- Получить помесячную динамику запросов
- Поля: `date`, `count`, `share`
- Это поможет планировать рекламные бюджеты по сезонам

### 6. Обработка ошибок

| HTTP-код | Что делать |
|---|---|
| 200 | Успех, обработать ответ |
| 429 | Квота исчерпана. Считать время до refill из ответа, ждать |
| 503 | Перегрузка API. Пауза 30 сек, повтор (до 3 раз) |
| 401/403 | Ошибка токена. Остановка с сообщением |
| Таймаут | Повтор через 5 сек (до 3 раз) |

Логирование всех ошибок в файл.

### 7. Хранение результатов

Основной формат — CSV с разделителем `;`:

```
маршрут;шаблон;фраза;total_count;top_1_phrase;top_1_count;top_2_phrase;top_2_count;top_3_phrase;top_3_count
Москва-СПб;такси {от} {куда};такси Москва Санкт-Петербург;12500;такси москва спб;8200;такси москва петербург цена;3100;...
```

Дополнительно — полный JSON-дамп каждого ответа для детального анализа позже.

### 8. Итоговый отчёт

После завершения сбора:

- **Топ-100 маршрутов** по суммарному totalCount (сумма по всем шаблонам)
- **Лучший шаблон** — какой шаблон даёт наибольшую частотность в среднем
- **Нулевые маршруты** — маршруты с нулевой или минимальной частотностью
- **Находки из associations** — неочевидные запросы, которые ищут пользователи
- **Общая статистика** — собрано фраз, потрачено квоты, время работы, ошибки

## Нефункциональные требования

### Стек

- Python 3.10+
- `requests` — HTTP-запросы
- `csv`, `json` — работа с данными
- `logging` — логирование
- `time`, `datetime` — управление паузами и таймстампы
- Без тяжёлых зависимостей

### Конфигурация

Файл `config.json`:

```json
{
  "token_env": "YANDEX_WORDSTAT_TOKEN",
  "routes_file": "routes.csv",
  "output_file": "wordstat_results.csv",
  "output_json": "wordstat_raw.jsonl",
  "templates": [
    "такси {from} {to}",
    "трансфер {from} {to}",
    "межгород {from} {to}",
    "такси {from} {to} цена",
    "{from} {to} на машине"
  ],
  "num_phrases": 50,
  "requests_per_second": 7,
  "regions": [],
  "devices": [],
  "collect_regions_top_n": 200,
  "collect_dynamics_top_n": 100,
  "resume": true
}
```

### Логирование

- Консоль: прогресс (обработано X/Y, осталось квоты Z, ETA)
- Файл `wordstat.log`: полный лог с таймстампами и ошибками

### Безопасность

- Токен — через переменную окружения `YANDEX_WORDSTAT_TOKEN`
- Не коммитить в репозиторий: config.json, *.csv, *.jsonl, *.log, progress.json
- `.gitignore` настроен

## Сценарии использования

```bash
# 1. Проверить квоту перед стартом
python main.py --check-quota

# 2. Первый запуск — полный сбор
python main.py

# 3. Прерван — продолжить с места остановки
python main.py   # автоматически подхватит progress.json

# 4. Сбросить прогресс и начать заново
python main.py --reset

# 5. Собрать только конкретные маршруты
python main.py --routes "Москва-СПб,Москва-Тула"

# 6. Собрать регионы для топ-маршрутов (после основного сбора)
python main.py --collect-regions

# 7. Собрать динамику для топ-маршрутов (после основного сбора)
python main.py --collect-dynamics

# 8. Сформировать отчёт по собранным данным
python main.py --report
```

|---|---|---|
